- **The review engine root must be established complete before it is executed on the file-read path.** The fix loop reaches `skills/review/SKILL.md` by an ordinary file read on three paths, and the acceptance predicate was that the read returned *something* carrying no truncation notice — but the engine root has no boundary-marker pair, and an over-cap read of a marker-less file returns a fragment with no notice at all, so a half-delivered merge gate was indistinguishable from a whole one and executed with no stop label. The canonical statement in `skills/review-and-fix/references/loop-control.md` Step 1 now establishes completeness by a **positive end-of-file confirmation** taken from the reader itself: after a read that appears whole, one further bounded read starting past the last line already held, which must return nothing beyond what is held — further content means the earlier read was truncated, so the caller pages forward and re-confirms. The paged arm terminates on that same confirmation rather than on "no continuation offered" or "a page added nothing new", neither of which distinguishes the file's end from a reader that stopped short of it. No byte or line count from an external tool is used, since none is guaranteed installed.
- **Candidate selection is re-cut onto path resolution, so exactly one arm can fire.** A path the reader reports as non-existent is *absent* and advances the list; a path that **resolves** is the selected candidate whatever the read returned, and no later candidate is read. A permission failure, a transient reader error, an oversize error returning no content, an empty or whitespace-only body, and an unclassifiable reader message are therefore a present-but-undelivered engine that leaves completeness *unestablished* — no longer swallowed as "absent" and no longer able to fall through to a different engine copy. Step 4 routes the two failures apart: no path resolving keeps the existing absent-engine fatal naming `/prflow:init`, while an unestablished body stops at the terminal `engine-root: incomplete`, which names the file, treats the body as unusable and repairs nothing.
- **An `engine-root: incomplete` non-convergence can no longer be soft-proceeded.** `skills/implement/phases/phase-3-fix-loop.md` routes it to that phase's Blocked path on both reachable paths and names the reflection to record there, so the durable record states the real cause instead of the path's unresolved-Critical literal — previously the engine never running satisfied "every residual was gradeable as non-Critical" vacuously and stamped the PR review-ready with no review having happened. `references/error-handling.md` and `references/shadow-review.md` point at the one canonical statement.
