## Quality group — visual presentation

**Once, before drafting the section**, check the user's resources — pasted images, attached files, URLs, design-tool links such as Figma — for a screenshot or mockup; when one is present, ask nothing. Otherwise ask one question via the runner's user-question tool: attach a screenshot or mockup, or confirm the visual details you propose — those that apply of placement & layout, visual states (hover/focus/error/empty/loading/disabled), responsive behavior across breakpoints, design-system/style match, and any the task makes relevant. A screenshot is preferred, not mandatory; a detail still unresolved after the question and Step 2's clarification routes goes to `## 🚫 Blocked` like any other.

- [ ] **The Visual Specification section records what that check obtained.** Either the screenshot or mockup — embedded inline when a hosted URL is available (`![description](https://…)`), otherwise referenced with a one-line note on how the implementer obtains it (attached file name, design-tool link) — or the confirmed visual details, only the dimensions that apply.
