## Embed arm (the on-disk draft path is untrusted here)

When `query-arm` answers `arm=embed`, the dispatch prompt embeds the full rendered draft title and body verbatim — carried in full, never condensed or summarized — as the sole draft source, and it does not carry the read-the-file instruction. The on-disk `issue-draft-<slug>.md` is untrusted on every entry path this arm has, so ignore it and audit the embedded body instead.

On this arm the out-of-bounds declaration names exactly these 10 files: `.prflow/tmp/create-issue/<slug>/issue-derivation-<slug>.md`, the Step 1 evidence artifact `.prflow/tmp/create-issue/<slug>/issue-step1-<slug>.md`, `.prflow/tmp/create-issue/<slug>/issue-draft-<slug>.md`, `.prflow/tmp/create-issue/<slug>/issue-audit-<slug>.md`, `.prflow/tmp/create-issue/<slug>/issue-audit-state-<slug>.json`, the retired `.prflow/tmp/create-issue/<slug>/issue-audit-state-<slug>.md`, any staged canonical-draft artifact `.prflow/tmp/create-issue/<slug>/issue-draft-<slug>.*.staged.md`, the investigation record `.prflow/tmp/create-issue/<slug>/issue-record-<slug>.md`, any dispatch-scope artifact `.prflow/tmp/create-issue/<slug>/issue-audit-scope-<slug>.*.md`, and the generated instruction file `.prflow/tmp/create-issue/<slug>/issue-audit-dispatch-<slug>.md`. The dispatch-scope glob is total, covering a round's own scope file too. The generated instruction file is named here and on no other arm.

### Carriage check

The tool generates the two sentinel tokens and prints them from `record-dispatch` (`sentinel_open=` / `sentinel_close=`). Bracket the embedded body with **exactly those printed tokens** — never tokens you choose yourself — and require the auditor to quote both sentinels plus the body's first and last lines verbatim in its return. **Forward the quoted pair to `record-return --carriage-sentinel-open <quoted> --carriage-sentinel-close <quoted>` and obey the classification returned**; the tool owns the comparison and fails closed on an absent tuple. Omit the flags when the return quoted no sentinels.

Steering-absence is unestablished by construction on this arm. Only the `write-failed` entry means the canonical draft-file write failed — `file-unreadable` follows a prior `VERDICT: DRAFT-UNREADABLE` in the current round (the within-round retry), and `digest-unrecorded` an entry whose file-arm comparand the tool could not establish or trust (its own hash failed, or the nonce is foreign to the record) — but on every entry this arm records no canonical dispatch-instruction file for the auditor to hash: pass no `--instructions-file` at `record-dispatch`, and the round records `steering=not-established steering_reason=no-instructions-file`. Withhold the coverage-backed clean grounding and carry the `audit independence unestablished` marker on the summary line beside this arm's embed marker — but filing is never blocked: the user's explicit approval still files through Step 4's documented override election. The same holds on the degraded inline arm below.

The Step 4 audit summary line carries the corresponding embed marker, which the tool records from the `--marker` you passed at dispatch and re-emits through `query-summary`.

## Retry escalations (each stays inside the round it retries)

- DRAFT-UNREADABLE retry: `record-return --verdict DRAFT-UNREADABLE` → `query-next-action` → `dispatch-embed-retry` → `record-dispatch --arm embed --marker file-unreadable --round "<round>"` (bytes on stdin, same round — no second round record); the embed arm hard-requires `--marker`, and `file-unreadable` is the marker `query-arm` answers for a prior `DRAFT-UNREADABLE`.
- File-arm same-arm retry escalating to embed: on a `dispatch-retry-same-arm` answer for a file-arm round, the canonical file can become unhashable between the return and the retry (a concurrent overwrite/delete). The tool permits escalating that retry to the embed arm rather than deadlocking — and the embed arm hard-requires `--marker`, so re-run `query-arm` and pass the marker it answers: `digest-unrecorded` when the file is now unhashable, or `file-unreadable` when a prior `DRAFT-UNREADABLE` is recorded (bytes on stdin, same round). The escalation is never silent — the marker is recorded in `embed_markers` and rendered in the summary.

## Degraded arm — attempt-first, never pre-detected

Dispatch whenever a subagent tool is exposed, nested contexts included — never pre-detect a nested context and skip. You reach this arm when the runner exposes no subagent-dispatch tool, when the dispatch call itself errors, or when `query-next-action` answers `dispatch-inline-degraded`; a *still-running* dispatch is awaited, never retried as a bad return.

On this arm, offer the round before running it — this arm runs only a round the user already elected at Step 4's pre-approval offer (recorded through `record-offer`, which funds it), so it never opens a round the user declined; a degradation that reached an in-chat round with no state owner offers it in chat first. Run the same audit prompt inline against the rendered draft, then record it — `record-dispatch --arm inline --round <round>` with the bytes on stdin, plus `record-degraded --round <round> --reason …`, each carrying `--round` — so the summary line is marked degraded. The degraded inline arm audits the rendered draft already in context, is exempt from the read-the-file instruction, and emits **no `VERDICT: DRAFT-UNREADABLE`** — that third value belongs to the file arm only.
