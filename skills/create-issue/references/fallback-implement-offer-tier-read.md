## Reading the implement tier when the resolver is denied or fails

When `references/step-4-present-create.md`'s leading-token `config-get.sh .workflows.prflow false` read is denied or fails, fall back to a direct read of the same key, anchoring the config path to the git repo root the same way `config-get.sh` does (the SHARED REPO-ROOT CONFIG CONTRACT: `ROOT=$(git rev-parse --show-toplevel 2>/dev/null || pwd)`).

Check file existence first with a bash builtin `test`, so an absent config is detected as the *unconfigured* state: `[ -f "$ROOT/.prflow/config.json" ] || { echo tier-unconfigured; }`. Only when the file exists do you read it with a preflight-guaranteed, classifier-permitted interpreter, using an extraction that mirrors `config-get.sh`'s `.workflows.prflow // false` on the value and type axes for every decision-relevant shape — boolean, string, absent key, wrong-type container, top-level non-object: a boolean `true` and a string `"true"` both read as `true`, while a wrong-type `workflows` container — or a top-level non-object config (a hand-corrupted `[]` or bare scalar) — reads as `false` rather than crashing. Use `python3 -c "import json,sys; d=json.load(open(sys.argv[1])); w=d.get('workflows') if isinstance(d,dict) else None; v=w['prflow'] if (isinstance(w,dict) and 'prflow' in w) else False; print(str(v).lower() if isinstance(v,bool) else str(v))" "$ROOT/.prflow/config.json"` or `jq -r 'if (type=="object") and ((.workflows|type)=="object") then (.workflows.prflow // false) else false end' "$ROOT/.prflow/config.json"`.

Lowercase only a JSON boolean and emit any other value verbatim, exactly as `config-get.sh` does; the compare is case-sensitive against the literal `true`, so a string `"true"` reads enabled while `"True"`/`"TRUE"` does not — never apply a blanket `.lower()`. Compare with bash builtins only (`case "$V" in true) … ;; esac`, or `[ "$V" = true ]`) — never `tr`/`sed` lowering. Do **not** narrow the fallback to a boolean-only `== true` test either: `config-get.sh` and the cloud gate accept a string `"true"` as enabled. The read is fail-closed: an absent key, an explicit `false`, a wrong-type shape, an absent file, and an unreadable/malformed config all resolve to something other than `true`, so the offer is withheld on each.

**Selecting between *tier disabled/unconfigured* and *config unreadable***

Inspect each rung's exit status, not its stdout alone: an empty stdout from a crashed rung must never be read as the value `false`. Classify by what was actually observed:
- The config file is absent (the `[ -f ]` guard above is false), or a rung read an existing file and returned a value at exit 0 that is not `true` (an absent key, an explicit `false`, a wrong-type `workflows` shape, a top-level non-object config) → *cloud implement tier disabled or unconfigured*.
- The file exists but every attempted read path failed to parse it — the resolver was denied/errored and the fallback interpreter errored on a genuine *parse or permission* failure, i.e. no rung ever established a value from a file that is present → use the distinct *config unreadable* reason. Never conflate it with *cloud implement tier disabled or unconfigured*.
