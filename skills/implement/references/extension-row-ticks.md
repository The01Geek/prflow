# Extension-row tick contract

Tick a `Skill extension resolved: ...` row only when the extension loader's complete output was observed in this context — its content read contiguously through the loader's own established completion (the trailing `load-prompt-extension.sh: PROMPT-EXTENSION-DIGEST:` line, whose value is the reported worker digest; a grep, line range, or preview that stops short of it is partial, never `observed-content`), or an observed empty result meaning no extension file. A parent's digest, byte count, summary, successful exit status, or preview alone does not establish that load, and neither does a compaction summary or a lost resident copy: an established load is reusable only in the context that read it whole under its existing residency rule. Never tick from recall. An already-ticked match is an idempotent no-op; only a genuine missing row calls for `--reconcile-extension-rows`. The terminal `workpad.py --status Complete` gate refuses completion while an extension row is unticked without a `state not established` note.

Complete-load recovery (implement intake, review-fix and finalization workers before substantive work; the parent before its documentation-stage dispatch). A delivery that arrives truncated — a preview with a saved-output path, a paged view, or any partial result — is not yet observed content: recover it first. Recover only through the native continuation or the saved-output path returned for that same loader invocation, reading contiguous content through established completion; a missing range, a truncation notice in the saved output, or an end-of-preview marker alone leaves it incomplete. At most one fresh full-load retry is permitted per extension-loading episode after the initial attempt, counted in the loading context; pagination and the not-found helper-location fallback do not spend it, and a retry requires an observed transient failure or an available permitted delivery setting that addresses the prior truncation. Repeating an unchanged truncation, bypassing a permission refusal, or retrying an actual parent/worker policy-identity mismatch is not permitted, and an unestablished retry count stops the episode rather than resetting the allowance. Recovery is read-only and preserves the inherited trusted extension root and the existing parent/worker digest comparison; it never reads the working-tree extension directly or replaces known policy with defaults. A root that cannot be preserved or an observed parent/worker digest mismatch stops before substantive work; a parent's changed digest from the sanctioned loader instead requires the complete refresh. An observed exit-0 empty result stays a valid no-extension state; a refused, missing, or still-incomplete result stays `state not established`, leaves the row unticked with its failure note, and returns the worker's existing stopped outcome naming the extension, the cause, and the recovery attempted, before any substantive work. At the parent checkpoint, record that cause and take the pre-dispatch Blocked path. A successful child load preserves any original parent-load failure note rather than claiming the parent observed it.

Unmet extension obligations (same three workers). A step the implement extension requires whose tool, MCP server or skill is refused only in its current form is first re-formed (the direct leading-token form, then any other permitted form; never the denied effect by another route). When no permitted form is left, write one `dropped-failed` reflection per unmet step — `extension obligation unmet: <step> — <capability> <reason>`, `<reason>` one of `not loaded`, `not permitted`, `not authenticated` — then skip the step, make no further attempt, and continue; the reflection discharges it, so it is neither an unresolved boundary in your return nor a blocking obligation for the parent. A skipped verification step stays unestablished, never passed — report it so, without stopping the run. A required step whose stated condition does not hold for the issue is skipped with no reflection.
