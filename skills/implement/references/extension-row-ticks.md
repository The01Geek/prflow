# Extension-row tick contract

Tick a `prompt extension resolved: ...` row only when the extension loader's complete output was observed in this context — its content read contiguously through the loader's own established completion, or an observed empty result meaning no extension file. A parent's digest, byte count, summary, successful exit status, or preview alone does not establish that load, and neither does a compaction summary or a lost resident copy: an established load is reusable only in the context that read it whole under its existing residency rule. Never tick from recall. An already-ticked match is an idempotent no-op; only a genuine missing row calls for `--reconcile-extension-rows`. The terminal `workpad.py --status Complete` gate refuses completion while an extension row is unticked without a `state not established` note.

Complete-load recovery (implement intake, review-fix, and finalization workers — before any substantive work). A delivery that arrives truncated — a preview with a saved-output path, a paged view, or any partial result — is not yet observed content: recover it first. Recover only through the native continuation or the saved-output path returned for that same loader invocation, reading contiguous content through established completion; a missing range, a truncation notice in the saved output, or an end-of-preview marker alone leaves it incomplete. At most one fresh full-load retry is permitted per extension-loading episode after the initial attempt, counted from the worker's own loader invocations; pagination and the not-found helper-location fallback do not spend it, and a retry requires an observed transient failure or an available permitted delivery setting that addresses the prior truncation. Repeating an unchanged truncation, bypassing a permission refusal, or retrying an actual policy-identity mismatch is not permitted, and an unestablished retry count stops the episode rather than resetting the allowance. Recovery is read-only and preserves the inherited trusted extension root and the existing parent/worker digest comparison; it never reads the working-tree extension directly or replaces known policy with defaults, and a root that cannot be preserved or an observed digest mismatch stops before substantive work. An observed exit-0 empty result stays a valid no-extension state; a refused, missing, or still-incomplete result stays `state not established`, leaves the row unticked with its failure note, and returns the worker's existing stopped outcome naming the extension, the cause, and the recovery attempted, before any substantive work. A successful child load preserves any original parent-load failure note rather than claiming the parent observed it.
