#### 2.3.0d Describing-prose reconciliation sweep (mandatory whenever the change removes a member from an enumerated value set, or weakens a universal it previously asserted)

2.3.0b catches an *addition* to an enumerated set leaving enumerating sites stale; 2.3.0a catches a newly-added rule stated at too few peers. This sweep catches the two edits neither of them arms on, and it has two authoritative triggers — run it when either fires:

- (a) Membership removal. The change removes a member from an enumerated value set.
- (b) Weakened universal. The change weakens a universal it previously asserted, by any of these three edits: softening it (an "always"/"every"/"never" becomes "usually"/"most"/"rarely"), scoping it (an unqualified claim gains a qualifier that narrows the population it ranges over), or removing it outright.

Both triggers are the same defect: the change made a claim false without editing the claim. The surviving sentence still parses, still reads plausibly, and is only *semantically* false — so it ships clean instead of being reconciled here.

Precedence — what this sweep does NOT cover, and which sweep owns each. A membership addition is §2.3.0b's, never this sweep's. Adding a rule that has co-equal peer sites is §2.3.0a's, never this sweep's. A rename — an addition and a removal at once — is assigned to §2.3.0b alone, because §2.3.0b's member-literal enumeration already reaches both the vacated literal and the arriving one; a rename does not additionally arm this sweep. (This precedence is about the membership family — §2.3.0b and §2.3.0d — only; a diff that independently arms other sweeps still runs each at the domain its own definition states, as it always has.)

Scope — the enumerated value set is not only code-shaped, matching §2.3.0b's own stated scope. A **doc-enumerated configuration set** counts: a workflow's `on:` trigger list, a config-key set, a permissions list. A removal from any of those arms trigger (a) exactly as removing a code enum member does.

After removing a member, or weakening a universal, before running tests:

0. Probe the tools this sweep's search form depends on, before searching, per the confirm-the-search-actually-ran rule in the §2.3 preamble in phase-2-sweeps-contract.md — `type rg` and `type tr` for whichever the form below uses, never `command -v`. Rung one of that ladder is the Grep tool, which the runner always provides, so an absent `rg` is a fall back to another rung rather than a degradation. The ladder is per search half, and a rung only substitutes for a capability it actually has — the Grep tool is line-oriented and cannot perform the `tr`-normalized search the hard-wrapped-copy half of trigger (b) needs, so an absent `tr` with no substitute for that half routes that half to the unrunnable arm even while the line-oriented half still runs and records its own evidence. Route a search half to the unrunnable arm at the end of this sweep when every rung available to *that half* is unavailable or refused, or when its search tool exits greater than 1 — and then do not reach step 3's evidence record.

1. Enumerate the describing prose by search, not from memory — two searches, because they find different things:
   - Describing prose that names no member literal. This is the case §2.3.0b's member-literal grep structurally cannot reach: a sentence describing *where the set came from*, *how many members it has*, *what its members have in common*, or *what the set is for*, which names no member and so matches no member-literal search. Locate it by searching for the set's defining symbol, heading, table, or file path — the constant name, the section title, the doc anchor — and read the surrounding prose, docstring, and block/header comments at every hit, including in files the diff never touched.
   - Surviving copies of the pre-change claim text (trigger (b)). Recover the pre-change wording from the **deletion hunks** of the §2.3 sweep operand (defined in the §2.3 preamble in phase-2-sweeps-contract.md — the merge base → working-tree branch delta) — then search for surviving byte-identical or near-identical copies of that claim elsewhere in the repo. A copy that a *different* file still asserts at full strength is exactly the defect this trigger exists to catch.

   Search domain and command form. The domain is the whole repository, not the diff: a surviving copy of a weakened universal characteristically lives in a *different directory* from the edit that weakened it, so a delta-bounded search cannot see it. Because a claim hard-wrapped at a different column lives on no single line, use the form **§2.3.0's *Relocation is a contract change too* step 2 already mandates in `<skill-dir>/references/sweep-2-3-0-changed-contract.md`** rather than inventing a second technique for the identical search — `grep -rnE` across the repo plus a `tr -s '[:space:]' ' '` normalization (excluding VCS, dependency, and build directories) — with the Grep tool or `rg` for the line-oriented half, per the grep-evidence rule in the §2.3 preamble in phase-2-sweeps-contract.md. Never `git grep`, which the implement profile does not grant.

2. **Reconcile each site, or record an explicit exemption.** Rewrite every surviving statement so it describes the post-change set, or the post-change *strength* of the claim. A site deliberately left as-is is allowed, but the asymmetry must be recorded with a `--note` (which site, why) — a *silent* falsified claim is the defect; a *documented* one is a decision.

3. Record the search result as evidence — only if step 0 passed and the searches ran. Per the grep-evidence rule in the §2.3 preamble in phase-2-sweeps-contract.md, record the match count plus "all reconciled" (or the specific stale sites you fixed) via `--note` — evidence, not a claim. If step 0 routed to the unrunnable arm, record *that* instead: this step's clean evidence note is never written over a search that did not run.

Unrunnable arm — an absent tool never yields silence, per the confirm-the-search-actually-ran rule in the §2.3 preamble in phase-2-sweeps-contract.md. When this sweep's enumeration cannot be run — a required tool is absent on the host, and equally when the search is denied by the runner's permission matcher — do not report a clean pass. Record `2.3.0d: unrunnable (<which search, which cause>)` via `--note`, naming the covering backstop — the Phase 3 review pass, and, when this sweep runs inside the fix loop, the Step 3.5 fix-delta gate plus the convergence shadow — then continue.

Termination is per fired trigger, never both unconditionally. The two searches serve different triggers — the defining-symbol search serves trigger (a), the deletion-hunk claim-text search serves trigger (b) — so a diff that fired only one trigger runs only that trigger's search, and is not done until *that* enumeration returns only prose consistent with the post-change set, or with the post-change strength of the claim (or an explicit `--note` for each exemption), or the unrunnable arm above has been recorded. A diff that fired both triggers owes both.
