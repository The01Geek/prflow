# Reference: Error Handling & Common Mistakes

## When NOT to use

- Not for trivial doc-only PRs — use `/prflow:review` and read the report; auto-fixing prose adds churn for little value. **Exception — engine-surface PRs are never "doc-only" for this purpose.** When the diff touches devflow's own engine surface — matched here by a **static path list**, not by reading any `diff_profile` flag (this bullet decides whether to enter the fix loop at all, before the engine has run and before any `diff_profile` exists): `skills/**`, `agents/**`, `lib/**`, **a prompt extension under the `.prflow/` or `.devflow/` state directory whose filename ends in `.md` at any depth, or a file whose basename is `CLAUDE.md` at any depth** — including changes that are *entirely* Markdown, like a SKILL.md, a prompt-extension, or a `CLAUDE.md` edit, `/prflow:review`'s Phase 0.5 sets `engine_self_modifying` and forces the **full** checklist, precisely because a typo there silently breaks every future review. Those changes are the highest-risk diffs in the repo, not low-value prose — so this doc-only carve-out does **not** apply to them: an all-Markdown engine-surface PR (including a prompt-extension-only or `CLAUDE.md`-only one) is unambiguously a valid `review-and-fix` target. The carve-out is only for low-risk prose (READMEs, `docs/`, comments) outside the engine surface.
- Not for PRs where you want to hand-review every finding before deciding — use `/prflow:review` instead; this skill commits fixes between iterations.
- Not for PRs that cross a release boundary or touch infrastructure where surprise commits would be costly — review-and-fix produces commits as a side effect of converging.
- Not for first-pass branch hygiene (rebases, conflict resolution, build fixes) — get a clean diff first, then run review-and-fix on the result.
- Not for situations where you need a formal `--request-changes` merge block as a side effect — this skill posts no formal review and no verdict comment. Its progress surface is the inline engine's run-keyed PR comment on a standalone PR-mode run, or the existing issue workpad on an implement-driven run. Run `/prflow:review <PR>` afterward (or instead) to post the verdict as a blocking review.

## Error Handling

- Agent failures: Treat as INCONCLUSIVE or note in report. Never abort the entire review. Exception — shadow reviewers (Step 2.6): this lenient rule does NOT apply to a shadow-pass reviewer failure. A shadow reviewer that fails, returns garbage, or is absent from the dispatched roster is a coverage shortfall that forces `coverage: "not_verified"` / outcome 3 (the shadow's fail-closed contract) — it must never be silently treated as INCONCLUSIVE-and-proceed, because that re-opens the false-clean path Step 2.6 exists to close. The *one* bounded concession (see Step 2.6 outcome 3's *Transient vs. structural* rule): a single transiently-failed reviewer gets exactly one targeted re-dispatch before `not_verified` is recorded; structural failures and any second/multi-reviewer failure are immediate `not_verified` with no retry. This is a single bounded retry, not the lenient INCONCLUSIVE-and-proceed path.
- Test failures after fixes: Fix the test failures before re-running the review loop.
- Commit failures: If a commit fails (e.g., pre-commit hook), fix the issue and retry the commit.
- Cannot locate /prflow:review's SKILL.md: Fatal only when none of the ordered, repo-root-anchored candidate engine directory paths (the repo-root `skills/review`, then `.prflow/vendor/prflow/skills/review`, then the superseded `.devflow/vendor/devflow/skills/review` — see Step 1, the canonical statement) resolves at all. Whichever candidate resolves first is the selected engine directory — the repo-root candidate is the normal self-review path — and Step 1's completeness predicate then decides whether that selection may be executed: a path that resolves but whose completeness could not be established (a reader error, an undelivered body, an empty body) takes Step 1's separate `engine-root: incomplete` terminal, not this one. When every candidate misses, error out with a clear message naming `/prflow:init` as the remedy; do not improvise by paraphrasing the phases, and do not silently fall back to a stale plugin-cache copy. (See "Engine source of truth" and the self-review callout in Step 1.)

## Common Mistakes

- Dropping the Loop Exit observability-persistence steps when this skill is driven interactively/inline by an orchestrator (rather than as a discrete end-to-end invocation). The fix loop, shadow passes, and fixes all run correctly, but the final *bookkeeping* — Step 3, item 6's fused per-iteration `iter-<N>.json` write (record shape in item 7), the effectiveness-trace render, and the `--persist` write of the record + durable workpad copy to the telemetry branch — gets silently skipped. These steps are mandatory on every writable run, not best-effort-optional. This applies with equal force to the sibling degraded path: when the orchestrator does not invoke this Skill at all but hand-runs the review engine via direct `Agent` dispatch (e.g. under cloud `claude-code-action` friction), the per-iteration `iter-<N>.json` write (Step 3, item 6; record shape in item 7) is still mandatory — a permission/sandbox denial is not license to leave the instrumented loop. The `lib/efficiency-trace.sh --persist` synthesis floor (specified authoritatively in fixing.md item 7) is a safety net, not license to skip the emit: it recovers only an effectiveness skeleton, not the per-phase cost half this loop alone captures live. **Dropping Loop Exit also leaves the final Blueprint row (*Run complete — everything this run owed*) unticked**, a known false negative of that drop mode rather than a delivery gap, since this loop posts no verdict to GitHub at all.
- Trying to skip Step 2.6 because iter N looked clean — the whole point of the shadow pass is that iter N's quietness might be undersampling. A clean iter that didn't survive shadow audit is not convergence.
- Re-posting the loop's verdict to GitHub via `gh pr review` from inside the loop — this skill posts no formal review and no verdict comment; progress remains on the inline engine's run-keyed PR comment for a standalone PR-mode run, or on the existing issue workpad for an implement-driven run. The user runs `/prflow:review <PR>` separately for a formal merge signal.
- Confusing Step 0.9's narrow-reuse signals with a wholesale Phase 1+2 skip — Phase 1+2 always re-run on iter ≥ 2; Step 0.9 only stages reuse INPUTS (Step 0.9 states this explicitly).
- Fixing only the literal instance a finding reports and leaving its `defect_signature.kind` siblings in the same diff for the shadow pass to rediscover — that converts one free deterministic sweep (Step 3, item 3) into multiple doubled-cost shadow promotions. Generalize every finding to its class and sweep the changed surface before committing.

## Post-return branch guard

The engine (Step 1) and shadow (Step 2.6) subagents share this checkout, so a ref-changing command one of them runs leaves the parent on the wrong branch and a later fix commit lands there silently. Their dispatch prompts forbid such commands, and after each subagent returns — before Step 2 for the engine, before Parse-and-compare for the shadow — run this guard against the recorded branch (PR mode: the Step 0.5 head ref; else the caller-held branch), mirroring Step 0.5's tool-result routing:

```bash
git rev-parse --abbrev-ref HEAD ; echo "branch-check-done"
```

Read the printed branch from the tool result. No output at all — the matcher refused the statement — is *unestablished*. A printed branch — the literal `HEAD` of a detached tree included — not equal to the recorded branch is a *mismatch*. Equal is *ok*: record `branch-check: <branch> ok` and proceed. On a *mismatch* with a clean tree (`git status --porcelain` prints nothing) run `git checkout <recorded-branch>`, re-run the check, and on a match record `branch-check: restored <from-ref> -> <branch>` and proceed. On a dirty tree, a failed `git checkout`, a re-check that still differs, or an *unestablished* reading, stop the loop at a non-convergence/blocked report naming both refs — the recorded branch and what `HEAD` reads — and make no fix commit.
